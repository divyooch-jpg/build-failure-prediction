# Build-Failure Prediction

Machine-learning project that predicts whether a CI build will **fail** or **pass**
from build metadata (commits, files changed, churn, coverage, author history, etc.).
Built for the *Automation in Software Development* assignment (Assignment_4_5).

## Project structure
```
src/generate_data.py   # creates data/builds.csv (synthetic CI build history)
src/train.py           # cleaning, feature engineering, training, evaluation
src/predict.py         # predict risk for a single new build
.github/workflows/ci.yml  # GitHub Actions: runs the whole pipeline on every push
results/               # metrics.json, plots, saved model
```

## Run locally
```bash
pip install -r requirements.txt
python src/generate_data.py
python src/train.py
python src/predict.py
```

## Models and results (test set, 20% split)
| Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| Logistic Regression | 0.7883 | 0.7897 | 0.7763 | 0.7829 |
| Random Forest | 0.7533 | 0.7579 | 0.7322 | 0.7448 |
| Gradient Boosting | 0.7583 | 0.7604 | 0.7424 | 0.7513 |

Best model: Logistic Regression (highest F1).

## CI
`.github/workflows/ci.yml` installs dependencies, regenerates the data, trains and
evaluates the models, and uploads `results/` as a build artifact.

## Note
The dataset is synthetic and generated by a rule that mimics real CI behaviour
(bigger changes, dependency updates, low coverage and earlier failures raise failure risk).
The same pipeline works with a real dataset such as TravisTorrent by replacing `data/builds.csv`.
